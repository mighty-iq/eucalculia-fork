# Eucalculia v7.2.0-md — community progression build

**Built on Eucalculia v7.1.22 by Alberto Flaño Lombardo, with his permission.**
Ideas and changes: **mighty_elf** and **.da.rk.** (Discord).
Everything is layered as one appended patch block at the end of the file (`<style id="euca-md-progression-style">` + `<script id="euca-md-progression-patch">`); Alberto's code is not edited in place.

## What changed

### 1. MEM cue restored to the v6.8.88 style
- Root cause of "I missed the meta popup every single time": the v7 patch `SPA-04-VISUAL-CLOSE` had moved `#memoryCue` out of the stimulus frame into the answer tray as plain grey text, with the amber colour, the pop and the ring stripped (`data-prompt-hosted`).
- Now: amber capsule back inside the frame (top-right; top-left on phones), bigger, with the v6 pop + ring animation; the whole frame glows amber while a retained item is on screen (orange for META², red-orange for META³).
- New **banner hold**: every MEM trial starts with a ~0.7 s hold on PREP showing "🧠 REMEMBER THIS PAIR · MEM¹ 1/2 · for META¹ · Retain the ORIGINAL values / TRANSFORMED values / LEFT and RIGHT as shown". Toggle in Settings → Progression.
- While a META question is being held back (see spacing), a dashed "HOLD · META¹ soon" pill stays visible so you know you are still carrying something.

### 2. META¹ says which values to use
Under every META¹ question: "Use the values **as shown** for both pairs" or "Use → Pair 1: **TRANSFORMED** values · Pair 2: values **as shown**". This removes the "transformed or original?" ambiguity at question time.

### 3. Progression modes (Settings → Progression)
| Mode | Tier rule | Level shown | Notes |
|---|---|---|---|
| **Baseline** | Alberto's v7.1.22 within-individual baseline, untouched | LV1–LV14 (tier) | RT-improvement gate is what holds people at a tier |
| **Staircase** (default) | Windowed accuracy at the current tier: up after a 20-trial window ≥85% (families gate kept), down if the last 12 < 60%. No RT gate. | LV 1–100 composite = 45% tier + 20% exposure + 20% META layer + 15% spacing | Post-cap "runway" bands (LV9–14) keep Alberto's META-evidence blockers |
| **Rating** | Elo/IRT rating θ (start 1060). Item difficulty δ = 800 + 55·tier + {0,230,420,600}[layer] + learned per-family offset. Tier = highest with expected success ≥80% (±15 hysteresis). | LV = 1 + (θ−1040)/10; rating shown next to it | Score: correct 0.75–1.0 by speed, wrong 0–0.2 by speed (deadlines 3.6/7.6/13/18 s for L0/META¹/²/³). K = 40 → 24 → 14. Item K = 8. |

Exposure time keeps Alberto's weighted up-down staircase in all modes (−5 ms correct / +30 ms error → converges at ≈86% correct).

### 4. Adaptive META spacing (Staircase and Rating)
Spacing level s = 0…5 (starts at 0). After 4 consecutive correct META answers s+1; after 2 wrong within the last 4, s−1.
- Between MEM 1/2 and MEM 2/2 (META¹ chains): interference lures with lag ⌈s/2⌉…s (s = 0 → none).
- Between the last retained item and the META question: exactly s ordinary trials (`plan._mdDueAt`).
No new chains open while a question is held.

### 5. Continuous META chain (eto's suggestion, toggle, on in the new modes)
When a META layer is genuinely *active* (not preview), a chain opens on the next eligible trial instead of by probability, and a new one opens right after a META is delivered.

### 6. Identity
`currentAppVersion()` → `v7.2.0-md`; title, version labels and summary footer updated; footer credit line + "About this build" card with the references.

## Frameworks
- Wilson, Shenhav, Straub & Cohen (2019) — 85% rule, Nat Commun 10:4646
- Levitt (1971) transformed up-down; Kaernbach (1991) weighted up-down
- Landauer & Bjork (1978) expanding retrieval; Bjork & Bjork (2011) desirable difficulties
- Klinkenberg, Straatemeier & van der Maas (2011) — Math Garden Elo adaptive practice
- Maris & van der Maas (2012) — speed-accuracy scoring rule
- UFOV/ACTIVE speed-of-processing training adapts display duration by staircase (Ball et al. 2002)

## Storage
Progression state lives in `localStorage["euca:md:prog:v2:p<profile>"]` — separate from Alberto's schema-validated profile. Reset of the active profile (trial counter back to 0) resets it too. Export/Import progress unaffected.

## Tested (headless Chromium, automated player)
- 130–230-trial sessions in each mode at 95% and 80% accuracy: no runtime errors, no flow violations, tier up/down, spacing up/down, block drain with held META questions.
- Cue/banner/hint/hold/summary/intro rendered on desktop (1100×860) and phone (412×880).
- Persistence across page reload.
- Wrapper-chain regression: the build keeps the same 6-layer `beginValidatedPrep` chain as the original (an earlier draft that wrapped it froze trials on content-pack items — removed).

## Known limits / ideas not done
- Composition-load budget per trial is not a separate axis yet (it still follows the tier, as in the original).
- Rating item difficulties are learned only from your own play (single-user Elo), so ratings are not comparable between people.
