## New in v1.5 — Dark's feedback, round three

### 1. 🔍 Peek — reveal a retained item during a META question
*"It's just dumb if you want to answer a question but can't because you're missing a single piece of memory… today I remembered 4-1 with middling certainty, and couldn't figure out a question; turns out it was 5-1."*

Under every META¹ / META² / META³ question there is now a **Peek** row:
- META¹: **Pair 1 LEFT · Pair 1 RIGHT · Pair 2 LEFT · Pair 2 RIGHT** (the *retained* values — transformed ones when the pair's rule said TRANSFORMED, labelled as such).
- META²: **Answer 1 · Answer 2** (the two 🧠²-marked META¹ answers) and **Question 1 · Question 2** (what each asked, with its answer).
- META³: **Question A · Question B** (what each META² asked, its corrected conclusion and its two answers).

Tap a button and the value appears in it. The question can then be answered on its merits — the reasoning still gets practised, which is what Dark asked for. The memory part is what the peek costs, and that is mighty_elf's condition ("we don't want you to level up in META difficulty because you did not get the memory aspect"):
- **Rating:** a peeked correct answer scores **0.5** instead of 0.75–1.0 — below the 80 % expectation, so it costs a few points rather than earning them; a peeked wrong answer scores as any wrong answer.
- **META spacing staircase:** counts as a **missed** memory (so the interval shortens rather than grows).
- **Alberto's META evidence** — the readiness windows that open META² / META³ in Auto, the lifetime per-op / per-layer stats behind the runway tiers, and the phase stats — all record the trial as **incorrect**. Nothing that unlocks a META layer or a post-cap tier can be earned with a peek.
- Untouched: your visible accuracy, streak and block stats (you did answer), the chain itself (the retained answer is what it is, so META² / META³ keep flowing), and the question's difficulty.
The block summary says how many questions were peeked. Staircase and Rating modes; Baseline keeps Alberto's rules. Toggle in Settings → Progression (**🔍 Peek on META questions**, on by default). The Learn coach mentions it on the first META¹ trials, and Learn → Vocabulary explains the cost.

### 2. META² / META³ say which answers they are about
*"There was an entire META question block and META² question block between, so it was impossible to tell what was asked for exactly."*
Under a META² question: **"About the two 🧠² MEM-marked META¹ answers: Answer 1 — 9 trials ago · Answer 2 — 3 trials ago"** (META³: Question A / Question B). The Peek row sits right under it if the memory is gone anyway.

### 3. The "weird hold" (a META question arriving as the 20th trial)
Two causes, both fixed:
- The v1.0 spacing hold for a due question was a **block-relative** deadline; Alberto's `resetBlock` carries a due chain into the next block, so after Menu → Start block (or a break) a leftover deadline could hold the question for most of the new block. The hold is now measured on the profile's trial counter and **cleared at every block start**.
- While a META¹ question was held, *no* META of any layer was dealt, so a due META² / META³ waited behind the META¹ hold and drifted towards the block end. A due META² / META³ is now dealt as soon as it is due; only the META¹ question itself waits for its spacing.
A delivery log (`EUCA_PROGRESSION.metaLog`: when each plan became due and when its question was dealt) is kept for diagnostics.

### 4. 📖 Term hints — "any1 a clue what 'role-based' means?"
Jargon in a question gets a dotted underline; tap or click it (or hover on desktop) for a short note. A **📖 n terms** chip in the frame's bottom row lists every term in the current question *and* its options (options themselves stay answer buttons). The notes are written from the generators' own code, not guessed — e.g.:
- **role-based** — values picked by their role inside a pair (the larger / the smaller), not by side;
- **side transfer / role transfer** — find the side of pair 1's larger value, read pair 2's value on that side;
- **same-named side readout** — LEFT with LEFT, RIGHT with RIGHT;
- **what LEFT leaves after groups of 3** — the remainder of LEFT ÷ 3 (Dark thought modulo — it *is* modulo);
- **finite-state machine / even/odd machine / division-by-3 machine** — what each machine actually tracks (digit-sum parity; remainder mod 3 of the number read so far);
- **counted halving / step count** — count the halvings until the value is odd (12 → 6 → 3 is 2 steps);
- plus witness, threshold, anchor, gap, parity, prime/composite, gcd/coprime, remainder, complement, Collatz, Euclid, ordinal pattern, implication, quantifier, exactly one / at least one / neither, mental line, proportion, balance, inverse operation, valid conclusion, calculation provenance… (58 entries).
Same notes in the review (correction) card, and the whole list — searchable — in **Learn → Vocabulary** (new lesson). Toggle: Settings → Progression → **Term hints**.

### 5. Negations stand out — "sometimes I overlook 'not' in the question and then sadness" — "Same"
*not · no · neither · nor · never · without · except · unless · cannot/isn't/doesn't… · none · non-… · other than · different from · exactly one · at least one · at most one · only* are shown in gold with an underline, in the question, the hint, the in-frame options, the tray options and the review card. Text content is unchanged (only spans are added), so Alberto's prompt-hygiene audits and screen readers see the same words. Toggle: **Highlight negations**.

### 6. Cards that left the rule unsaid (base defect)
*"Trace source: start from RIGHT · Recursive rule: run the inner recursive rule while tracking the step count · Question: Is the final step count exactly 2?" — "don't know what that is"* — and the finite-state-machine question nobody could parse.
The structured card's "Recursive rule" row is generic for two families and the sentence that named the machine is trimmed away by the base's prompt hygiene. The fork now states the actual rule on the card:
- counted iteration → *count the steps of this inner rule: if the value is even, halve it; stop when it is odd — the step count is the number of halvings (12 → 6 → 3 is 2 steps; an odd start is 0 steps)*;
- finite automaton → *the even/odd machine: start in EVEN; every odd digit (LEFT first, then RIGHT) flips EVEN ↔ ODD…* / *the division-by-3 machine: start at remainder 0; after each digit the state becomes (10 × state + digit) mod 3…*.

### 7. "Every whole number can be divided by 1 without a remainder" (base defect)
*Build LEFT and RIGHT so the answer is YES: Can the sum be divided by the smaller number with no remainder?* — Dark built (1, 10) and was marked wrong, because the generator's verifier excludes a smaller value of 1 (to avoid trivial pairs) without saying so. Same for *Is the larger number a multiple of the difference?* with a difference of 1. Those two prompts now **reject** such pairs with an explanation ("Use values where the smaller one is greater than 1 — every whole number divides by 1, so a 1 would make the question trivial") instead of calling a mathematically correct pair wrong. Flashed YES/NO questions never used those pairs, so nothing else changes.

### 8. Rotation card: the viewpoint belongs to the instruction
*"'Quarter-turn counterclockwise' and 'from behind the figure' should both be written in white, so you intuitively know they belong together."* Done — the viewpoint line ("FROM BEHIND THE FIGURE" / "FROM YOUR PERSPECTIVE") is white and bold like the instruction; "Apply it to every cube" and the view anchor keep their colours.

### 9. The "seal" ✨
*"Let the Eucalculia logo in the after-round card glow up for a second — finishing a block seals your progress."* Alberto's crest on the block summary now pulses with a ring and a shine when the summary opens; gold and a little longer on a level milestone. Respects reduced-motion; toggle **Summary shine**.

### 11. "any1 seeing a difference between 3 and 4? xD" — paper folding (base defect)
Two things:
- **Visually identical candidates.** The generator builds the three distractors from the eight symmetry images (rotations / reflections) of the correct hole pattern and removes only *exact* duplicates (same 5-decimal key). A hole set that is symmetric up to rounding therefore keeps two cards that differ by a hair — and in most of those cases one of the two is the correct one, so the question was a coin flip. Measured on the base generator: **20–27 %** of items contain such a pair by Alberto's own distinctness rule from the later masked-paper family (Hausdorff distance ≥ 0.14 of the sheet and at least two holes moved) — 27 % over seeds 1–400, 20 % over 400 random 32-bit seeds — and in three quarters of those the twin is the correct card; in 13 % two cards are identical to within 0.0005. The diagonal fold plans are the worst (40 %). The fork now checks every paper-folding item before it is shown and rebuilds it from another seed (same fold plan first) — at most 5 attempts were ever needed. The trial object, the fold sequence style and the answer buttons stay as they are; the item's seed is recorded (`trialInfo.__mdPaperRepaired`).
- **Sheet size.** The four candidates sat in a 2×2 grid inside a wide box, so on a PC at 1366×768 each sheet was 61 px. They now sit in **one row** with the fold sequence above them: sheets ~95 px on that PC (123 px at 1080p), the fold vignettes 85 px instead of 55 px, and the punch marks drawn a little bolder. Phones keep the same sheet size they had (the width is the limit there).

### 12. "Do the two numbers have different square-number status and different multiple-of-3 status?" — the pair Dark could not find
Dark tried 9/4 and 10/5 (both NO). The correction card only said "Build a pair that makes the claim YES". It now shows **a pair that works** — the one closest to the player's own pair — and, for the two-property questions, **why**: *A pair that makes the claim YES — for example LEFT 9, RIGHT 5* · *Why LEFT 9, RIGHT 5 works: LEFT 9 — a square number: yes, a multiple of 3: yes · RIGHT 5 — a square number: no, a multiple of 3: no → different on "a square number", different on "a multiple of 3".* The search uses the task's own verifier, value range and distinctness / domain rules (so for *sum divisible by the smaller* it never proposes a 1). Glossary entries added for **square-number status**, **multiple-of-3 status**, **prime status** and **matched / mismatched (agree / disagree) on** — "different X status" simply means exactly one of the two values has X.

### 13. "Some of the meta questions are very cringely asked — 'is at least one of these true' … it should just be a true or false answer, not a concretisation"
Those are the nested yes/no questions (level 6+): the stem is a yes/no question but every option names a *pattern* — *YES — only (1) holds*, *NO — neither (1) nor (2) holds*. The verdict prefix is the answer to the stem; the rest says which branches hold (the base added the prefixes in v6.8.4 precisely because the stem used to be answered by none of the options). The options cannot change in a fork without changing the item itself, so the fork now explains the format where it is needed: a line under the question — **Two-part answer: decide (1) and (2) separately, then pick the option that names which of them hold — its YES/NO prefix is the verdict (YES when (1) or (2) holds — or both; NO only when neither does)** — with the connective's meaning filled in for *both true / at least one true / exactly one true / at least one false / both false*; the stem phrase gets a term note and the gold scope highlight; and the META lesson in Learn has a paragraph on it.
Dark's idea — the plain YES/NO version as a lower META level and the four-way version as a higher one — is a generator-level change (a second option format per nested item, with its own chance level, evidence and audits). Recorded as design for a later version rather than bolted on here; see *Known limits / ideas*.

### 14. Android: "it works when I open it, but when I come back to the tab later it shows *Your file couldn't be accessed* (ERR_FILE_NOT_FOUND)"
What happens: opening the HTML from the Files app gives Chrome a one-time permission for a `content://media/…` link. That permission only covers the first load — Chrome cannot *re-read* the file by itself. So anything that reloads the tab ends on that error page, and the file has to be opened from Files again (progress is kept: it lives in the browser's storage, not in the file).
What the fork did differently from the base: the base never reloads itself, and all of Alberto's scroll areas keep the pull gesture away from the browser (`overscroll-behavior: contain`). The fork's own scroll areas — the Learn lesson body and rail, the About card, the term panel — did not, so dragging down at the top of a lesson could reach Chrome's **pull-to-refresh**, which reloads the page. Fixed: every fork scroll area contains its overscroll, and the page root refuses overscroll actions altogether (pull-to-refresh, edge swipe-back), so no gesture can reload the page any more. When the file was opened through a `content://` link, Settings → Progression also shows a short note with what to do if it still happens (a tab Chrome itself had to restore after Android killed it in the background can't be helped by any page — that is the same for the base).
Not a memory issue: with forced garbage collection the fork's JS heap over 120 trials is the same as the base's (45 MB vs 49 MB).

## Known limits / ideas
- The glossary covers the recurring abstract terms; a question that uses a word not in it simply shows no underline — send the screenshot and it gets added.
- Peek reveals the retained item, not the rule of the current question; the term hints cover the rule words.
- mighty_elf's larger idea — separate progression axes for the memory load and the question complexity of META — is not in this version; the spacing staircase remains the memory axis, and peeks only ever lower it.
- Dark's two-level idea for the nested yes/no questions — a plain YES/NO version as a lower META level, the four-way "which branches hold" version as a higher one — is recorded as design. It needs a second option format per nested item inside the generator (its own chance level, its own evidence for the depth ladder and the nested-Boolean audits), so it is a proper generator change for a later version, not a wrapper.
- The paper-folding rebuild only covers the full-unfold items of the visual-predict family; the later masked-paper family already applies the same distinctness rule in the base.
