# Eucalculia Fork v1.1 (base v7.1.22)

**A fork of Eucalculia v7.1.22 by Alberto Flaño Lombardo, built with his permission.**
Ideas and changes: **mighty_elf** and **.da.rk.** (Discord), jointly.

The fork is versioned on its own from now on: **v1.0** is the build that was published as "v7.2.0-md";
this is **v1.1**. In-app the version string is `v7.1.22-fork.1.1` (keeps the app's `vX.Y.Z` contract for
exports/diagnostics) and the label people see is "Eucalculia Fork v1.1 · base v7.1.22".
Alberto's code is never edited in place: everything lives in two appended patch blocks at the end of the
file (`euca-md-progression-*` and `euca-md-learn-*`), so a future base version can be re-patched.

## New in v1.1

### 1. Learn — a step-by-step tutorial system
Menu → **🎓 Learn — tutorial** (next to Guide). Eight short lessons in a left rail, each one page:

| # | Lesson | What it does |
|---|---|---|
| 1 | How Eucalculia works | The path (numerical sense → manipulation → relational → META¹/²/³), one trial step by step with the real timings (PREP 250 ms, exposure 750→70 / 1330→600 ms, mask 150 ms), blocks, Auto path. |
| 2 | Reading the formats | Live gallery of all 15 formats drawn by the game's own renderers, with the reading rule of each (coins copper/silver/gold = 1/2/5, abacus red = 5, cards A/J/Q/K = 1/11/12/13, …), values toggle, new examples, and a "What number?" practice quiz. |
| 3 | Flash, mask, answer | The real trial rhythm on a demo stage: exposure slider 70–1330 ms, format selector, numpad answer, feedback that shows the stimulus again. Explains exposure adaptation, auto-submitting numbers, "don't count". |
| 4 | Relational questions | LEFT/RIGHT demo with a random question from a 20-item bank (compare, negated compare, equality, parity, sum/threshold, distance, primes, divisibility, direction, "closer to 10"…), the family table, the phrasing traps (not / neither / exactly one / at least one), and the other shapes: build-a-pair, choose-one, spatial. |
| 5 | Transformed readings | "as shown" vs "TRANSFORMED", practice with the real transform rules (opposite die face, ten-frame/grid complement, clock +3 / opposite hour, folded fingers, tally to next bundle, abacus upper row) and a table of every transformation family in the app. |
| 6 | MEM & META chains | The chain diagram (MEM¹ 1/2 → spacing → MEM¹ 2/2 → HOLD → META¹), how the cue/banner/glow announce it, what to retain, META² and META³, and a full playable chain with an optional distractor trial. |
| 7 | Levels & progression | Live status of the active profile (mode, LV, exposure, META layer, spacing, next-tier blocker), the three modes explained, what a tier is, the runway bands, the numerical-sense ladder, and a button to Settings → Progression. |
| 8 | Controls & settings | Keyboard map, review card, menu/resume, summary, profiles, export/import, plus the coach toggle and tutorial reset. |

Supporting pieces:
- **Welcome card** in the menu for a fresh profile ("First time here? Take the 5-minute tutorial" · Start / Skip). Non-blocking; disappears once the tutorial has been opened, skipped, or 20 trials have been played.
- **? HELP** chip next to Menu during a block (desktop widths): pauses the block (`openMenuEmergencySafe`) and opens the lesson that matches the trial on screen (numerical sense → formats, manipulation → transforms, relational → relational, META/MEM → chains). Resume works as usual afterwards.
- **Coach strip** above the answer buttons: one-line hint for the current trial kind (subitize, transform, LEFT/RIGHT bool/number/choice, exact distance, build-a-pair, spatial, META¹/²/³, retained pairs), shown for the first 8 trials of each kind, then quiet. "hide" turns it off; Learn → Controls turns it back on or resets the counters. It never reveals hidden information (interference lures stay unmarked).
- Progress per profile in `localStorage["euca:md:learn:v1:p<profile>"]` (lessons read, last lesson, welcome state, coach state, per-kind hint counters). Alberto's profile format untouched.
- Keyboard: Esc closes, ← / → change lesson, Tab is trapped in the panel (the app's own focus trap is pointed at it), Y/N/←/→, 0–9 + Enter and 1–4 answer the practice questions. Space cannot start a block while the panel is open.
- Works on phones (single column, lesson rail becomes a horizontal strip) — the HELP chip is hidden below 560 px; the coach strip keeps its own "?" button, becomes a compact two-line strip on phones, and hides itself on very short screens (< 640 px high) so the numpad always stays fully on screen (checked at 412×880, 390×844, 375×700, 360×640).

### 2. Fixes found during the verification pass
- **Built-in audit suite**: `auditAdaptiveBaseline` now passes through to Alberto's rule while it runs (the new modes step aside), so `runFeatureAudit('all')` gives exactly the same results as the untouched v7.1.22 (diff: none).
- **META deferral**: while any META question is being held back (spacing), no META trial of any layer is dealt any more (previously only the held layer was blocked) — the interposed trials are plain L0.
- **About card**: Escape now closes it (the app's window-level Escape handler stops propagation before element listeners run) and Tab stays inside it.
- Fork identity everywhere: title, footer version label, credit line, About card, Settings → Progression label, summary footer.

## Carried over from v1.0 ("v7.2.0-md")

### MEM cue restored to the v6.8.88 style
- Root cause of "I missed the meta popup every single time": the v7 patch `SPA-04-VISUAL-CLOSE` had moved `#memoryCue` out of the stimulus frame into the answer tray as plain grey text.
- Now: amber capsule back inside the frame (top-right; top-left on phones), with the v6 pop + ring; the frame glows amber (orange for META², red-orange for META³) while a retained item is on screen.
- **Banner hold**: every MEM trial starts with a ~0.7 s hold on PREP: "🧠 REMEMBER THIS PAIR · MEM¹ 1/2 · for META¹ · Retain the ORIGINAL / TRANSFORMED values / LEFT and RIGHT as shown". Toggle in Settings → Progression.
- While a META question is held back, a dashed "HOLD · META¹ soon" pill stays visible.

### META¹ says which values to use
Under every META¹ question: "Use the values **as shown** for both pairs" or "Use → Pair 1: **TRANSFORMED** values · Pair 2: values **as shown**".

### Progression modes (Settings → Progression)
| Mode | Tier rule | Level shown |
|---|---|---|
| **Baseline** | Alberto's v7.1.22 within-individual baseline, untouched (RT-improvement gate is what holds people at a tier) | LV1–LV14 (tier) |
| **Staircase** (default) | Windowed accuracy at the current tier: up after a 20-trial window ≥85 % (families gate kept), down if the last 12 < 60 %. No RT gate. | LV 1–100 = 45 % tier + 20 % exposure + 20 % META layer + 15 % spacing |
| **Rating** | Elo/IRT rating θ (start 1060). δ = 800 + 55·tier + {0,230,420,600}[layer] + learned per-family offset. Tier = highest with expected success ≥ 80 % (±15 hysteresis). Score: correct 0.75–1.0 by speed, wrong 0–0.2 by speed (deadlines 3.6/7.6/13/18 s). K 40→24→14, item K 8. | LV = 1 + (θ−1040)/10, rating shown next to it |

Post-cap "runway" bands (LV9–14 in tier terms) keep Alberto's META-evidence blockers. Exposure keeps Alberto's weighted up-down staircase in all modes.

### Adaptive META spacing (Staircase and Rating)
Spacing level s = 0…5. After 4 consecutive correct META answers s+1; after 2 wrong within the last 4, s−1. Interference lures between MEM 1/2 and 2/2 with lag ⌈s/2⌉…s; exactly s ordinary trials between the last retained item and the question. No new chain opens while a question is held.

### Continuous META chain (eto's suggestion, toggle, on in the new modes)
When a META layer is genuinely active, a chain opens on the next eligible trial instead of by probability, and a new one opens right after a META is delivered. Applies to Staircase and Rating.

### Frameworks
Wilson, Shenhav, Straub & Cohen (2019) 85 % rule · Levitt (1971) / Kaernbach (1991) staircases · Landauer & Bjork (1978) expanding retrieval · Klinkenberg, Straatemeier & van der Maas (2011) Math Garden Elo · Maris & van der Maas (2012) speed-accuracy scoring · Ball et al. (2002) UFOV exposure staircase.

## Verification (headless Chromium, automated player)
- `runFeatureAudit('all')` + every global `audit*` function + all registered audit handlers: identical statuses to the untouched v7.1.22 base; zero runtime errors, zero page errors.
- Play sessions with the tutorial patch active: Staircase 170 trials @95 %, Rating 130 @80 %, Baseline 110 @90 %, plus a 320-trial Staircase session @97 % — no runtime errors, no flow violations; tiers, spacing, deferral, META¹/META² all exercised; coach counters classify every trial kind met (subitize, transform, posner, posner+mem, posner_tr, meta1, meta1+mem, meta2, witness, spatial, build, choice).
- Tutorial: every lesson rendered and every practice demo played end-to-end by script (formats quiz, flash demo, relational demo, transform demo, full META¹ chain) on desktop 1200×900 and phone 412×880; keyboard paths (Esc, ← →, Space/Enter on buttons, Shift+Tab wrap, digits/Enter, Y/N); Space never starts a block behind the panel; HELP chip pauses and resumes correctly; Guide and About still work; tutorial progress separate per profile and persistent across reload.
- Stimulus renderers: all 15 formats × values 1–20 render without error inside the tutorial canvases.

## Known limits / ideas
- Composition-load budget per trial is not a separate axis yet (follows the tier, as in the original).
- Rating item difficulties are learned from your own play only (single-user Elo).
- The tutorial is English-only (the app's i18n layer is not used by the patch).
