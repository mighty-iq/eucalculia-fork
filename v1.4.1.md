## New in v1.4.1 — eto's follow-up ("maybe yes" to choosing the META layer by hand) + Dark's PC clipping report

### 1. META layer selectable by hand
The level card's manual block (menu → "What moves it now", Staircase and Rating modes, once the relational phase has started) has a third row, **META layer**: **Auto · No META · META¹ · META² · META³**.

- **Auto** (default, unchanged) is Alberto's rule: layers open on META evidence and never run more than one above the tier (his "pyramid" cap). Nothing changes for anyone who leaves it there — eto's own point that META²/³ may not be where the potential is stays fully respected: the setting is opt-in and per profile.
- A layer set by hand is treated as **active**: its chains open from the next eligible trial (with the Continuous META chain toggle, right away), the usual **briefing card** comes first the first time a layer appears, block size follows Alberto's rule (30 trials when META³ is on), and the HUD / level card / block summary show the layer with a "manual" mark. The tier, exposure, spacing and transfer rules keep adapting as before.
- **No META** = relational LEFT/RIGHT questions only; no chains open.
- Choosing a **lower** layer than what is running drops the chains that were still collecting above it (the user said stop); a question that was already **due** (both items retained) is still asked once, so a promised 🧠 cue never dangles. Switching back to **Auto** returns to whatever the evidence says — the evidence bookkeeping kept running underneath the whole time, and META answers given under a forced layer count as evidence, so a forced layer can also be a way to earn the META evidence the post-cap runway tiers ask for.
- Baseline keeps Alberto's rules untouched: the row is disabled there (hint says so). The setting is stored with the fork's progression state (`euca:md:prog`), never in Alberto's profile format, and every change is logged (`manualMetaChanges`).

How it is done (for the technically minded): Alberto forces `metaAuto = true` at every start and retired the public manual-level control in v7, so flipping his flag would be fought by the app. Instead the fork overlays the chosen layer on `dAutoSnapshot()` — the one place every consumer reads from (`effectiveMetaLevel`, `dMetaPresence`, the chain openers, the briefing cards, block size, HUD) — while his hysteresis and readiness bookkeeping continue on the real evidence underneath. The audit suite passes through to the un-overlaid snapshot.

### 2. Fix: META² / META³ questions were held back by the spacing rule
The v1.0 spacing staircase held **every** META question for `s` trials after its second retained item. A META² / META³ question retains two whole META¹ / META² episodes, so its retention interval is already a full chain long; holding it as well pushed the higher questions to the block end, where Alberto's drain rule (rightly) opens no new top-level chain — so at spacing ≥ 3 a META³ chain could never start, in Auto as well as by hand. The hold now applies to **META¹ only** (interference lures already did); META² and META³ are asked as soon as their second item is in, as in the original. For the same reason the **auto block size grows with the spacing** when META² or META³ is on — Alberto's 20 / 30 stay the floor, up to 60 (≈ 1.25 META cycles of the top layer: a META³ cycle is ≈ 11 + 7·s trials at spacing s), shown as "auto→N" in the menu — so that one full cycle fits before the block-end drain. Level-card, About and Learn texts say so.

### 3. Dark's report: "sometimes it's a bit out of frame at the bottom" (PC)
Reproduced exactly with his screenshot's trial type (the fraction builder, "Make the new picture show the same fraction …"): the Learn **coach strip** sat *inside* the answer tray, which has a fixed height, so whenever a hint was showing the panel below it lost the strip's ~44 px. Most panels just shrink a little (his "cuts away a slight bit"); the builder panel cannot shrink, so its READY button went 18–21 px below the tray's edge at every common PC window size (1920×1080, 1536×864, 1440×900, 1366×768, 1280×720; 40 px at 650 px-high windows) and was clipped — the worst case in his picture.
Fix: the strip is now its **own row between the stimulus frame and the tray** (the frame gives up the height, never the answer buttons), and the row is **reserved for the whole block** while the coach can still speak, with an invisible placeholder of fixed height (44 px desktop / 36 px phone), so the frame keeps one height from flash to answer instead of jumping when a hint appears. It still hides on very short screens (≤ 640 px high).
Verified: READY sits 27–30 px *above* the tray edge at all the sizes above; a 500-trial tray audit across every answer surface the app produces (numpad, YES/NO, 3/4-way choice, build-a-pair, induction, L1 constructive, program, balance, visual-predict, fraction builder) on 1366×768 and 412×880 shows zero clipped pixels with and without the strip; frame height within a block only changes when Alberto's own per-panel tray heights change (212/228/252 px), never because of the strip.

## Known limits / ideas
- At high spacing (4–5) a META³ cycle is long (two META² episodes, each two META¹ chains with their spacing), so blocks that carry a META³ chain extend well past 30 trials — that is Alberto's promise-keeping drain, kept on purpose.
- Composition-load budget per trial is not a separate axis; rating item difficulties are learned from your own play only; the Learn tutorial is English-only.
